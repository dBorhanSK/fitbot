# ربات تلگرامی مربیگری تناسب اندام

پشته: Python + Flask + Telegram Webhook + Supabase + Render.

## امکانات پیاده‌سازی‌شده
- منوی شیشه‌ای (Inline Keyboard) برای تغذیه، تمرین باشگاه، تمرین منزل، مشاوره، سوابق/رضایت و بازخورد
- افزودن خدمات و قیمت از طریق دستور مدیریتی
- فرم مرحله‌ای برای ثبت اطلاعات مشتری
- ثبت سفارش و جداسازی سفارش‌ها بر اساس شناسه عددی تلگرام مشتری
- دریافت رسید عکس/فایل و ارسال آن برای مالک جهت بررسی
- تأیید/رد دستی رسید توسط مالک
- پیام تأیید سفارش با زمان آماده‌سازی ۳ تا ۴ روز کاری
- ارسال متن برنامه اختصاصی با دستور مدیریتی
- مسیرهای `/health` و `/ready` و اعتبارسنجی secret وب‌هوک
- ذخیره‌سازی ماندگار در Supabase

## راه‌اندازی

### 1) ساخت ربات
در تلگرام به `@BotFather` پیام بده، `/newbot` را اجرا کن و توکن را بردار.
شناسه عددی مالک را از یک ربات نمایش‌دهنده User ID یا ابزار معتبر تلگرام بگیر.
توکن ربات و کلیدهای Supabase را عمومی یا داخل کد منتشر نکن.

### 2) ساخت دیتابیس Supabase
در پروژه Supabase به SQL Editor برو، محتوای `schema.sql` را اجرا کن.
از Project Settings / API مقدار Project URL و `service_role` secret key را بردار. فقط در Environment Variables سرور Render قرار بده؛ این کلید دسترسی مدیریتی دارد.

### 3) انتشار در Render
این پوشه را در یک مخزن GitHub شخصی آپلود کن و در Render گزینه New Web Service را به مخزن وصل کن. فایل `render.yaml` تنظیمات اصلی را تعریف می‌کند.
در Environment Variables این مقادیر را وارد کن:
- `BOT_TOKEN`: توکن BotFather
- `WEBHOOK_SECRET`: رشته تصادفی محرمانه، فقط شامل حروف انگلیسی، عدد، `_` و `-`، حداقل 32 کاراکتر
- `OWNER_ID`: آیدی عددی تلگرام مالک
- `SUPABASE_URL`: آدرس پروژه
- `SUPABASE_SERVICE_ROLE_KEY`: کلید service_role
- `PUBLIC_BASE_URL`: آدرس سرویس Render، مثل `https://your-service.onrender.com` (بدون اسلش انتهایی)
- `SETUP_KEY`: یک کلید تصادفی جداگانه برای راه‌اندازی وب‌هوک
- `COACH_USERNAME`: آیدی عمومی مربی بدون @
- `PORTFOLIO_TEXT`: متن سوابق و رضایت‌ها؛ در صورت نیاز با `\n` جدا کن

پس از Deploy، این آدرس باید پاسخ سالم بدهد:
`https://your-service.onrender.com/health`

یک‌بار وب‌هوک را تنظیم کن:
`https://your-service.onrender.com/set-webhook?key=YOUR_SETUP_KEY`
این URL حاوی کلید راه‌اندازی است؛ آن را با کسی به اشتراک نگذار. بعد از موفقیت، می‌توانی `SETUP_KEY` را از Environment Variables حذف/خالی کنی تا endpoint دوباره قابل استفاده نباشد.

### 4) دستورات مالک
- `/admin` پنل مدیریت
- `/addservice nutrition|نام برنامه|250000|توضیحات` افزودن خدمت
- `/addservice gym|برنامه قدرتی|300000|مناسب سطح متوسط` افزودن برنامه باشگاه
- `/addservice home|تمرین منزل|200000|بدون تجهیزات` افزودن برنامه منزل
- `/delservice 3` غیرفعال کردن خدمت شماره 3
- `/deliver 12` و سپس فرستادن متن برنامه برای سفارش شماره 12
- `/addportfolio عنوان سابقه|توضیحات` افزودن سابقه یا نمونه‌کار به بخش عمومی
- `/delportfolio 2` غیرفعال کردن سابقه شماره 2
- مشتری‌ها از بخش «سوابق و رضایت مشتریان» نظر ثبت می‌کنند؛ نظر ابتدا برای مالک می‌رود و فقط بعد از تأیید منتشر می‌شود.

دسته‌ها دقیقاً `nutrition`، `gym` و `home` هستند. قیمت به تومان و به صورت عدد وارد شود.

## نکات مهم
- رسید فقط به عنوان «ارسال‌شده برای بررسی» ثبت می‌شود؛ تأیید نهایی فقط با دکمه مالک انجام می‌شود.
- پرداخت آنلاین در این نسخه وجود ندارد؛ پرداخت دستی و بررسی رسید است.
- فایل رسید با `file_id` تلگرام نگه‌داری می‌شود و برای مالک فوروارد می‌شود؛ برنامه‌های متنی در دیتابیس ذخیره می‌شوند. برای تحویل PDF/عکس برنامه، فایل را جداگانه در چت مشتری ارسال کنید.
- سوابق/نمونه‌کارها توسط مالک از خود ربات اضافه و غیرفعال می‌شوند. نظرهای مشتریان قبل از انتشار به تأیید مالک نیاز دارند.
- وضعیت رایگان Render پس از ۱۵ دقیقه بدون ترافیک ممکن است به خواب برود و اولین درخواست بعد از خواب می‌تواند حدود یک دقیقه یا بیشتر تأخیر داشته باشد. Keep-alive تضمین نمی‌کند سرویس رایگان همیشه بیدار بماند. Health Check فقط سلامت را می‌سنجد و تضمین پاسخ فوری نمی‌دهد.
- مسیر `/health` عمداً بدون درخواست دیتابیس سریع پاسخ می‌دهد؛ `/ready` اتصال دیتابیس را هم بررسی می‌کند.
- این پروژه برای شروع و تست است؛ قبل از استفاده واقعی، تست انتها‌به‌انتها، پشتیبان‌گیری و سیاست حریم خصوصی را انجام بده.
- اطلاعات سلامت و بدنی مشتریان حساس‌اند؛ فقط اطلاعات لازم را جمع‌آوری کن و دسترسی دیتابیس را محدود نگه دار.
